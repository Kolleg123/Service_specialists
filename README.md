## Запуск на Windows

Требуется **Python 3.12 или новее**. Команды ниже предназначены для обычной **командной строки Windows (CMD)**.

1. Откройте CMD в корневой папке проекта — в ней должны находиться `app.py` и `requirements.txt`.
2. Проверьте, что установлен Python 3.12 или новее:

   ```cmd
   py --version
   ```

   Если команда `py` не найдена, попробуйте `python --version`. Если Python не установлен, установите его с [официального сайта](https://www.python.org/downloads/windows/) и включите добавление Python в PATH.

3. Создайте виртуальное окружение (этот шаг нужен только при первом запуске):

   ```cmd
   py -m venv .venv
   ```

   Если команда `py` недоступна, но работает `python`, используйте `python -m venv .venv`. Если папка `.venv` уже существует, повторно создавать окружение не нужно.

4. Активируйте виртуальное окружение:

   ```cmd
   .venv\Scripts\activate.bat
   ```

   В начале строки CMD появится префикс `(.venv)`.

5. Установите зависимости:

   ```cmd
   python -m pip install -r requirements.txt
   ```

6. Запустите приложение:

   ```cmd
   python app.py
   ```

7. Откройте в браузере [http://127.0.0.1:5000](http://127.0.0.1:5000).

**Важно:** не закрывайте окно CMD, пока работает приложение. Чтобы остановить сервер, нажмите `Ctrl+C` в этом окне. При следующем запуске откройте CMD в папке проекта, активируйте существующее окружение и выполните `python app.py` — создавать `.venv` и устанавливать зависимости повторно не требуется.

Если не хотите активировать окружение, можно выполнять команды напрямую через его Python:

```cmd
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

## Запуск на Linux и macOS

Требуется Python 3.12 или новее.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

Откройте [http://127.0.0.1:5000](http://127.0.0.1:5000).

SQLite создаётся автоматически при первом запуске в `instance/svobodno.sqlite`. Перезапуск сохраняет данные. Порт по умолчанию — **5000**; его можно изменить переменной окружения `PORT`. Это демонстрационный сервер Flask; для публичной эксплуатации необходим production WSGI-сервер, HTTPS и отдельная настройка безопасности.

## Что реализовано

- Каталог шести специалистов, категории, поиск по имени/специализации/услугам/навыкам, фильтры стоимости и формата, сортировка.
- Профиль: стаж, навыки, образование, услуги, стоимость, продолжительность, отзывы.
- Выбор услуги, даты и **существующего свободного слота**, адрес выезда и комментарий.
- Индивидуальные записи и группы: количество участников, доступные места, серверная проверка вместимости в транзакции SQLite. Два параллельных запроса не могут переполнить слот.
- Отмена предстоящей записи клиентом, назначенным мастером или администратором. Места возвращаются в доступные.
- Клиент: история записей/вызовов, поиск, собственные отзывы и статусы модерации.
- Мастер: добавление услуг, индивидуальных и групповых слотов, защита от пересечения расписания, закрытие незанятого слота, отмена и завершение встреч.
- Администратор: публикация/отклонение отзывов, скрытие/возврат специалистов и услуг, просмотр/отмена записей.
- Консультационный помощник: подбор по ключевым словам, например «протекает кран» → сантехник. Это **правила, а не LLM**. Чат не является прямой перепиской с мастером.
- Адаптивный интерфейс, сессии, хеширование паролей, CSRF-проверка, серверные ограничения прав.

Все даты и время относятся к **Кирову, UTC+3 (Europe/Kirov)**. Предзаполненное расписание создаётся на 14 дней вперёд относительно первого запуска. В дальнейшем мастер добавляет слоты самостоятельно. Групповое занятие — один слот вместимостью до 50 человек. Интервалы включают длительность услуги; время на дорогу мастер учитывает при размещении слотов.

## Проверка полного цикла

1. Войти клиентом, выбрать сантехника, услугу, день и свободное время; указать демонстрационный адрес и подтвердить.
2. Убедиться, что встреча появилась в кабинете и слот занят. Отменить — слот снова свободен.
3. Выбрать Анну Лебедеву → «Разговорный клуб» и указать несколько участников. Из другого аккаунта проверить остаток мест.
4. Войти мастером: добавить услугу и слот. Пересекающийся интервал отклоняется. Слот с активными записями нельзя закрыть без их отмены.
5. В кабинете клиента есть завершённая демонстрационная встреча с сантехником: оставить отзыв.
6. Войти администратором, опубликовать отзыв. Он появится в профиле специалиста и повлияет на рейтинг.
7. В чате написать «протекает кран» и перейти к рекомендованному специалисту.

## Редизайн и запись без устаревшего выбора

В `requirements.txt` добавлена `tzdata==2025.2`, чтобы `ZoneInfo('Europe/Kirov')` работал и в системах без установленной базы часовых поясов.

Запись разделена на три этапа: **услуга → дата и время → подтверждение**. Выбор другой услуги сразу очищает дату, время и итоговый экран, сообщает причину и запрашивает расписание заново. Запоздавший ответ для прежней услуги игнорируется. Даты доступны страницами по четыре, кнопками «Назад» / «Далее» и полем «Перейти к дате». Даты не генерируются искусственно: интерфейс показывает, до какого дня мастер опубликовал расписание. На последней странице кнопка «Далее» отключена с пояснением, что новые слоты добавляет мастер.

Перед отправкой записи UI повторно загружает доступность и проверяет количество участников, дату, длительность и цену. Сам POST повторяет проверку в транзакции `BEGIN IMMEDIATE`: из двух запросов на последнее место проходит только один. После конфликта выбор сбрасывается, загружаются актуальные альтернативы. При смене услуги и ошибках сети доступно понятное сообщение; при недоступности сервера — кнопка повторной загрузки и таймаут 15 секунд. Во время отправки переключение услуги заблокировано.

Доступность привязана к услуге: свободное начало короткой услуги **не переносится** на длинную услугу. Интервалы вычисляются по длительности услуги. Даже если в импортированных данных или после изменения длительности появились пересечения, занятый интервал исключается из доступных и блокируется при POST.

Помощник расположен в потоке страницы перед фильтрами: не перекрывает карточки при прокрутке. Фотографии карточек имеют единый формат 4:3 и `object-fit: contain`, поэтому исходный кадр с лицом не обрезается. Подписи используют русские формы «1 отзыв», «2 отзыва», «5 отзывов», включая 11–14 и составные числа.

## Завершение встречи и правила статусов

**Окончание = начало слота + длительность услуги в минутах.** Завершить встречу можно ровно с расчётного окончания (`now >= ends_at`), включая переход через полночь. Часовой пояс — Киров, UTC+3; решение принимает сервер с точностью до секунд без округления к минуте. Время берётся после получения блокировки записи, поэтому ожидание конкурентного запроса не сохраняет устаревшее право отмены.

В базе сохранены совместимые статусы `confirmed`, `cancelled`, `completed`. Внутри `confirmed` интерфейс различает три временные фазы:

| Статус / фаза | Условие | Клиент | Назначенный мастер | Администратор |
|---|---|---|---|---|
| Предстоит (`confirmed/upcoming`) | Сейчас раньше начала | Отменить свою запись | Отменить свою запись | Отменить любую запись |
| Идёт встреча (`confirmed/in_progress`) | Начало ≤ сейчас < окончание | Просмотр; отмена/отзыв недоступны | Просмотр; завершение пока недоступно | Просмотр |
| Ожидает завершения (`confirmed/awaiting_completion`) | Сейчас ≥ окончание | Ожидает подтверждения мастера | Завершить оказанную услугу | Просмотр |
| Завершена (`completed`) | Мастер подтвердил после окончания | Один отзыв, затем его статус | Просмотр | Просмотр и модерация отзыва |
| Отменена (`cancelled`) | Отмена до начала | Просмотр, без отзыва | Просмотр | Просмотр |

- **Отмена:** только до начала (`now < starts_at`), клиентом-владельцем, назначенным мастером либо администратором. Ровно в момент начала отмена уже запрещена. Отмена освобождает количество забронированных мест, но не удаляет историю.
- **Завершение:** только назначенным мастером, только из `confirmed`, только после расчётного окончания. Клиент, другой мастер и администратор не могут подтвердить оказание услуги. Достижение времени окончания само по себе не завершает запись.
- **Перенос:** в текущем демо это отмена до начала и отдельная новая запись на доступный слот. Автоматического переноса нет; новое место не резервируется отменой, поэтому наличие нового времени нужно проверить отдельно. После начала отмена/перенос через приложение недоступны.
- **Неявка:** не определяется по часам и не превращается автоматически в оказанную услугу. Такая запись остаётся «Ожидает завершения»; стороны уточняют ситуацию вне приложения. Отдельного статуса/кнопки неявки в этом этапе нет. Мастер подтверждает завершение только фактически оказанной услуги, а отзыв до такого подтверждения недоступен.
- **Повторные запросы:** повторное завершение или отмена возвращает `409 {"error": "..."}`. `cancelled` и `completed` — конечные состояния, повторно открыть их нельзя. Чужая запись не меняется. Проверка и запись статуса выполняются в одной транзакции `BEGIN IMMEDIATE`.
- **Отзыв:** требуется собственная `completed`-запись и наступившее расчётное окончание. Дополнительная проверка времени защищает и старые ошибочно завершённые записи; их исторические статусы и отзывы автоматически не переписываются. Повторный отзыв даёт 409.

`GET /api/dashboard` сохраняет прежние поля и дополнительно возвращает `ends_at`, `phase`, `status_label`, `actions`, `action_reasons`; верхнеуровневое `server_now` отражает часы сервера. Оба кабинета используют одну серверную политику. Недоступные действия не отображаются кнопками, рядом показано объяснение ограничения. Статус обновляется кнопкой «Обновить статусы», после действий и каждые 30 секунд на открытой вкладке записей, если пользователь не работает с диалогом/элементом кабинета. Фильтр сохраняется. При устаревшем экране сервер всё равно повторно проверяет действие.

## Восстановление начальных данных

Инициализация больше не завершает работу при обнаружении первого специалиста. `seed_data.py` создаёт недостающие демо-объекты одной транзакцией; при ошибке данные этой попытки откатываются. Два запуска сериализуются SQLite. Следующий запуск восстанавливает отсутствующие части.

`seed_entities` хранит соответствие стабильного ключа демо-объекта его ID. Существующие строки **не заменяются**: имена, пароли, скрытые услуги, цены, закрытые слоты, клиентские записи и отзывы остаются неизменными. Если стандартный ID занят сторонними данными, используется свободный ID и реальные связи; помощник также использует соответствие, а не жёстко заданный ID.

`seed_meta.anchor_date` фиксирует исходную дату расписания: каждый запуск не создаёт новые 14 дней и не дублирует историю. На старой базе без метаданных дата восстанавливается по самому раннему обычному слоту демо-услуг, исключая исторические демонстрационные встречи; если осталась только демонстрационная история — по её дате плюс семь дней; если нет ни расписания, ни истории — берётся текущая дата. Старые строки распознаются по естественным ключам (почта, специалист/услуга, услуга/время, запись отзыва). Для произвольно изменённых до миграции естественных ключей происхождение восстановить невозможно: строка сохраняется, а отсутствующий стандартный демо-объект может быть добавлен отдельно. Инициализатор восстанавливает пропуски, но не является инструментом ремонта произвольного повреждения схемы.

Тесты покрывают базу с одним специалистом, пропуски записей и метаданных, полный старый набор без меток, коллизии ID, прерывание, параллельный запуск и повторный запуск спустя месяцы. Снимки пользовательских строк сравниваются до/после, включая пароли, модерацию и реальные бронирования.

## Проверка этого этапа

```bash
source .venv/bin/activate
pytest -q
node --check static/app.js
node --check static/booking.js
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
# Обновить снимки кабинетов, используя только временную тестовую базу:
CAPTURE_LIFECYCLE=1 CHROMIUM_PATH=/usr/bin/chromium npx playwright test tests/browser/lifecycle.spec.js
```

Серверные тесты используют фиксированные часы: до начала, в момент начала, за секунду до окончания, ровно в окончание, после окончания и при переходе через полночь. Браузерный сценарий проходит реальную запись, ранний отказ, разрешённое завершение назначенным мастером, повторный отказ и отправку отзыва клиентом. Часы переключает только `scripts/e2e_server.py` в отдельной временной базе на loopback; производственный `create_app()` и запуск `python app.py` маршрута управления часами не содержат (это тоже проверено тестом).
