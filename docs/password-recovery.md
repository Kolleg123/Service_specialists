# Восстановление пароля по email (T-036–T-039)

## Архитектура и предположения

Функциональность встроена в существующий Flask API и SQLite. Хеширование паролей остаётся на Werkzeug. SMTP реализован стандартной библиотекой Python, без новых зависимостей. Таблицы создаются идемпотентно в общей схеме приложения; существующие записи не изменяются.

## Поток

1. Пользователь отправляет email через `POST /api/password-reset/request` (JSON, CSRF).
2. Email нормализуется и проверяется. Для существующего аккаунта создаётся криптографически случайный токен; в БД сохраняется только SHA-256 токена. Старый активный токен заменяется.
3. Письмо содержит ссылку `/reset-password?token=...`; срок действия — 30 минут.
4. Страница отправляет токен, новый пароль и подтверждение в `POST /api/password-reset/confirm`.
5. В транзакции токен проверяется, пароль хешируется, все токены пользователя удаляются. Повторное применение невозможно.

Оба endpoint используют существующую CSRF-защиту приложения. Запросы ограничиваются тремя попытками на IP или хеш email за 60 минут. Ответ запроса одинаков для существующего и неизвестного адреса. Ошибка SMTP не раскрывает адрес или наличие аккаунта клиенту; в лог попадает только безопасное сообщение без содержимого исключения.

## Конфигурация

Скопируйте `.env.example` в локальную конфигурацию окружения и задайте `APP_BASE_URL`, `APP_SECRET`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`, `SMTP_FROM_NAME`. Реальные секреты не коммитить. Для production обязательны HTTPS и `COOKIE_SECURE=true`. SMTP-порт 587 использует STARTTLS.

## Сценарии и критерии приёмки

| Сценарий / действия | Ожидаемое поведение | Критерий прохождения |
|---|---|---|
| Успех: запросить ссылку, открыть её, задать совпадающий новый пароль | Письмо отправлено; пароль изменён; токен удалён | Вход работает с новым паролем, старый пароль не работает |
| Незарегистрированный email: отправить адрес без аккаунта | Тот же нейтральный ответ; письмо не отправляется | Ответ не позволяет определить наличие аккаунта |
| Некорректный email: отправить неверный формат | Ошибка валидации | HTTP 400, токен не создаётся |
| Просроченный токен: открыть ссылку позднее 30 минут | Отказ в изменении пароля | HTTP 400, пароль не изменён |
| Повторное использование: отправить тот же токен повторно | Отказ | Второй запрос получает HTTP 400 |
| Некорректный пароль: длина вне 8–128 или несовпадающее подтверждение | Отказ до изменения БД | Пароль остаётся прежним |
| SMTP недоступен: запросить восстановление | Нейтральный ответ пользователю; безопасная запись в лог | Секреты и токен не попадают в лог |
| Повторные запросы: сделать более трёх запросов за час с одного IP/email | Дальнейшая отправка не выполняется | Ответ остаётся нейтральным; лимит соблюдён |

## Автоматические проверки

Тесты используют временную SQLite БД и подмену отправителя письма через `MAIL_SENDER`; реальный SMTP не нужен. Запуск: `python -m pytest -q`.

## Ограничения

Flask использует подписанные cookie-сессии без серверного реестра сессий. Существующие сессии на других устройствах нельзя немедленно отозвать без отдельного механизма версионирования/хранилища сессий; после восстановления текущая cookie очищается. Для production рекомендуется мониторинг SMTP, HTTPS, дополнительный rate limiting на reverse proxy и резервное копирование SQLite.
