# Восстановление пароля по email (T-036–T-039)

## Архитектура и предположения

Функциональность встроена в существующий Flask API и SQLite. Хеширование паролей остаётся на Werkzeug. SMTP реализован стандартной библиотекой Python, через smtplib; python-dotenv загружает локальный файл окружения. Таблицы создаются идемпотентно в общей схеме приложения; существующие записи не изменяются.

## Поток

1. Пользователь отправляет email через `POST /api/password-reset/request` (JSON, CSRF).
2. Email нормализуется и проверяется. Для существующего аккаунта создаётся криптографически случайный токен; в БД сохраняется только SHA-256 токена. Ранее выданные ссылки остаются действительными до истечения срока или первого успешного сброса.
3. Письмо содержит ссылку `/reset-password#token=...`; срок действия — 30 минут. Фрагмент ссылки браузер не отправляет в HTTP-запросе, поэтому новый токен не попадает в журналы доступа по URL.
4. Страница отправляет токен, новый пароль и подтверждение в `POST /api/password-reset/confirm`.
5. В транзакции токен проверяется, пароль хешируется, все токены пользователя удаляются. Повторное применение невозможно.

Оба маршрута используют CSRF-защиту. За 60 минут допускается до 3 запросов на адрес, до 30 с одного IPv4 или IPv6-префикса /64 и до 150 на экземпляр базы. Учёт ведётся в SQLite, поэтому несколько веб-процессов делят лимиты. Действующие и неизвестные адреса получают одинаковый статус и тело ответа. Проверка токена и его отзыв вместе с остальными ссылками на этот аккаунт выполняются транзакционно.

Отправку выносит в фон ограниченная очередь в каждом процессе приложения. SMTP-ошибка журналируется по типу исключения, токен для недоставленного сообщения отзывается, а новые попытки в этом процессе пропускаются в течение пяти минут. После перезапуска или переполнения очереди пользователь при необходимости запрашивает новое письмо. При использовании Nginx настройте [доверенный IP прокси](runtime-and-yookassa.md#nginx-и-https).

## Конфигурация

Скопируйте `.env.example` в файл `.env` в корне проекта (рядом с `app.py`). Приложение загружает его автоматически при старте. Файл `.env` не добавляйте в Git. Задайте `APP_BASE_URL`, `APP_SECRET`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`, `SMTP_FROM_NAME`. Реальные секреты не коммитить. Для production обязательны HTTPS и `COOKIE_SECURE=true`. SMTP-порт 587 использует STARTTLS, порт 465 — TLS сразу при подключении. Для Gmail укажите `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, полный адрес в `SMTP_USERNAME`, а в `SMTP_PASSWORD` — пароль приложения (не обычный пароль аккаунта; у Google должна быть включена двухэтапная проверка). `SMTP_FROM_EMAIL` обычно должен совпадать с авторизованным отправителем.

После настройки перезапустите Flask. При проблеме доставки серверный лог покажет тип ошибки (например, `SMTPAuthenticationError`, `SMTPConnectError` или `RuntimeError`), не раскрывая пароль, токен или адрес пользователя. Если лог сообщает `RuntimeError`, проверьте `SMTP_HOST` и `SMTP_FROM_EMAIL`; если SMTP authentication — проверьте логин и пароль приложения. Проверьте также папку «Спам» и ограничения почтового провайдера.

## Сценарии и критерии приёмки

| Сценарий / действия | Ожидаемое поведение | Критерий прохождения |
|---|---|---|
| Успех: запросить ссылку, открыть её, задать совпадающий новый пароль | Письмо отправлено; пароль изменён; токен удалён | Вход работает с новым паролем, старый пароль не работает |
| Незарегистрированный email: отправить адрес без аккаунта | Тот же нейтральный ответ; письмо не отправляется | HTTP-статус и тело ответа совпадают |
| Некорректный email: отправить неверный формат | Ошибка валидации | HTTP 400, токен не создаётся |
| Просроченный токен: открыть ссылку позднее 30 минут | Отказ в изменении пароля | HTTP 400, пароль не изменён |
| Повторное использование: отправить тот же токен повторно | Отказ | Второй запрос получает HTTP 400 |
| Некорректный пароль: длина вне 8–128 или несовпадающее подтверждение | Отказ до изменения БД | Пароль остаётся прежним |
| SMTP недоступен: запросить восстановление | Нейтральный ответ пользователю; безопасная запись в лог | Секреты и токен не попадают в лог |
| Повторные запросы: сделать более трёх запросов за час для одного адреса | Дальнейшая отправка не выполняется | Ответ остаётся нейтральным; лимит соблюдён |

## Автоматические проверки

Тесты используют временную SQLite БД и подмену отправителя письма через `MAIL_SENDER`; реальный SMTP не нужен. Запуск `python -m pytest -q tests/test_password_recovery.py tests/test_pm_final_tasks.py`.

## Ограничения

Flask использует подписанные cookie с версией сессии из таблицы пользователей. При сбросе или смене пароля эта версия увеличивается. Смена пароля из профиля выдаёт новый сеанс в текущем браузере. Старые cookie перестают проходить проверку. Выход из кабинета отзывает текущий сеанс.
